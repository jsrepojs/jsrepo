Plugins are the way to extend **jsrepo**. A single plugin can add [providers](/docs/providers), [languages](/docs/languages), [transforms](/docs/transforms), and settings for `jsrepo build` all at once.

## Using plugins

Add plugins to the top level `plugins` array of your config:

```ts title="jsrepo.config.ts"
import { defineConfig } from "jsrepo";
import prettier from "@jsrepo/transform-prettier"; // [!code ++]
import shadcn from "@jsrepo/shadcn"; // [!code ++]

export default defineConfig({
	plugins: [prettier(), shadcn()], // [!code ++]
});
```

You can also let the CLI install the plugin and update your config for you:

```sh
jsrepo config plugin @jsrepo/transform-prettier @jsrepo/shadcn
```

### How plugins are applied

- **Providers** and **languages** from plugins are checked _before_ the defaults, so you don't need to spread `DEFAULT_PROVIDERS` or `DEFAULT_LANGS` to keep them.
- **Transforms** (and `build.transforms`) run in the order they are configured. Anything in your top level `transforms` runs first, followed by plugins in the order of the `plugins` array.
- **Remote dependency resolvers** run in order, each one receiving the result of the previous one.
- **Hooks** run after the `hooks` in your config, in the order of the `plugins` array. Plugin hooks run for every command, so use the `command` argument to limit them to the commands you care about.

## Plugin authors

A plugin is an object with a `name` and any of the following:

<TypeTable
	type={{
		name: {
			description: "The name of the plugin. Used in error messages.",
			type: "string",
			required: true,
		},
		providers: {
			description: "Providers the plugin adds.",
			type: "ProviderFactory[]",
		},
		languages: {
			description: "Languages the plugin adds.",
			type: "Language[]",
		},
		transforms: {
			description: "Transforms that run on items when they are added to a project.",
			type: "Transform[]",
		},
		"build.transforms": {
			description: "Transforms that run on files before they are added to the built registry.",
			type: "BuildTransform[]",
		},
		"build.remoteDependencyResolver": {
			description: "Rewrites remote dependencies when building the registry.",
			type: "RemoteDependencyResolver",
		},
		hooks: {
			description: "Functions or shell commands to run before and after CLI commands.",
			type: "{ before?: BeforeHook | BeforeHook[]; after?: AfterHook | AfterHook[] }",
		},
	}}
/>

To make your plugin installable with `jsrepo config plugin`:

1. Name your package `jsrepo-<name>` or `@<org>/jsrepo-<name>` (a `plugin-`, `provider-`, `language-` or `transform-` prefix after `jsrepo-` is fine)
2. Export a function that returns the plugin as the `default` export

The name of your plugin in the config will be the name of your package without the `jsrepo-` prefix (and type prefix) converted to camel case.

```plaintext
jsrepo-my-plugin -> myPlugin
@my-org/jsrepo-transform-my-transform -> myTransform
@jsrepo/transform-prettier -> prettier
```

```ts title="src/index.ts"
import type { Plugin } from "jsrepo";
import { myProvider } from "./provider";
import { myResolver } from "./resolver";

export default function myPlugin(): Plugin {
	return {
		name: "my-plugin",
		providers: [myProvider()],
		build: { remoteDependencyResolver: myResolver },
	};
}
```

### Compatibility with the legacy options

The top level `providers`, `languages`, `transforms` and `build` options still work exactly as before. If you want your package to keep working for users on those options, return an object that is both a plugin and the legacy type:

```ts title="src/index.ts"
import type { Plugin, Transform } from "jsrepo";

export default function myTransform(): Plugin & Transform {
	const transform: Transform = {
		transform: async ({ code }) => ({ code: code.trim() }),
	};

	// works with `transforms: [myTransform()]` and `plugins: [myTransform()]`
	return { ...transform, name: "my-transform", transforms: [transform] };
}
```

<Callout type="info">
	Don't add the same plugin to both `transforms` and `plugins` or it will run twice.
</Callout>
